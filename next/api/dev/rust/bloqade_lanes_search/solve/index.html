solve ¶

bloqade_lanes_search::solve

High-level solver that ties together the lane index, expander, heuristic, and A* search into a single reusable object.

MoveSolver is constructed once per architecture (parsing JSON and building indexes) and can then solve multiple placement problems.

Solve a loose-goal entangling placement + routing problem.

Instead of fixed target locations, the solver receives CZ pair constraints and simultaneously discovers both the entangling placement and the routing. The goal is satisfied when every CZ pair occupies a valid entangling position (same zone, entangling word pair, same site).

Arguments

Section titled “Arguments”
  • `initial` — Starting qubit positions: `(qubit_id, location)` pairs.
  • `cz_pairs` — Required CZ pairs: `(qubit_a, qubit_b)` that must end up at entangling positions.
  • `blocked` — Locations occupied by external atoms (immovable obstacles).
  • `max_expansions` — Optional limit on node expansions.
  • `opts` — Search-tuning parameters (strategy, weight, restarts, etc.).

Returns

Section titled “Returns”

A SolveResult whose goal_config contains the discovered entangling placement.

bloqade_lanes_search::solve::MoveSolver::solve_entangling_rh

Parameters

max_expansions Option&lt;u32&gt;
opts &amp;SolveOptions
ent_opts &amp;EntanglingOptions

future_cz_layers &amp;[Vec&lt;(u32, u32)&gt;]

Returns

Result<SolveResult, ConfigError>

Receding-horizon (MPC-style) loose-goal entangling solve.

Instead of committing to one Hungarian assignment up-front like solve_entangling, this entry runs a sequence of K-candidate-rollout stages. At each stage:

  1. Generate K diverse Hungarian candidates from the current state.
  2. Roll out each for `rollout_horizon` move layers via the existing IDS infrastructure.
  3. Pick the best branch by stratified score (tier-0: goal reached mid-rollout; tier-1: completed full horizon; tier-2: dropped).
  4. Commit the winning branch’s path (full for tier-0, `commit_depth` layers for tier-1) and re-plan from the new state.

Restarts wrap the entire trajectory: `opts.restarts` parallel calls, each running its own independent receding-horizon trajectory with a distinct seed; `pick_best` returns the lowest-layer-count winner.

Positioned as a tool for high-occupancy regimes where the baseline loose-goal under-uses parallelism. See `docs/superpowers/plans/2026-05-11-receding-horizon-loose-goal-design.md`.

Result<SolveResult, ConfigError>

Two-phase no-home placement: return assignment + entangling routing.

Phase 1 generates up to `1 + nohome_opts.top_bus_signatures` candidate home layouts (Hungarian with lane-signature reward variants), routes each via solve, and keeps the candidate whose return-routing produces the fewest move layers (the hop-count substitute for routing time).

Phase 2 picks one CZ-staging target per pair via a deterministic per-pair rule (cross-word pairs prefer moving the qubit at home; same-word pairs default to moving the control), then routes once.

Arguments

Section titled “Arguments”
  • `initial` — Starting qubit positions (typically post-CZ).
  • `cz_pairs` — Required CZ pairs for the next layer.
  • `blocked` — Immovable obstacle locations.
  • `max_expansions` — Budget for node expansions (shared across phases).
  • `opts` — Search-tuning parameters for the routing phases.
  • `nohome_opts` — Tuning parameters for the return assignment.
  • `future_cz_layers` — Future CZ layers; gamma-decayed partner distances bias the Phase-1 home assignment toward future-friendly layouts via `nohome_opts.lambda_lookahead`.

Errors

Section titled “Errors”

Returns ConfigError if `initial` contains duplicate qubit IDs.

class SolveOptions ¶ source

bloqade_lanes_search::solve::SolveOptions

Bases: Debug , Clone , Default

Rust struct. Core search-tuning parameters shared by every [`MoveSolver`] entry point.

pub struct SolveOptions

Fields

Name Type Description
strategy Strategy Search strategy to use.
weight f64 Heuristic weight for A* (1.0 = standard, >1.0 = bounded suboptimal).
restarts u32 Number of parallel restarts with perturbed scoring (1 = no restarts).
deadlock_policy DeadlockPolicy How to handle deadlocks (no improving moves).
lookahead bool Enable 2-step lookahead scoring inside [`HeuristicGenerator`]. Affects every strategy that goes through that generator.
top_c Option&lt;usize&gt; Per-qubit move-candidate pruning passed to [`HeuristicGenerator`]. `None` keeps all scored triples (default for the basic [`solve`] path); `Some(n)` keeps the top `n` bus options per qubit by score. [`solve_entangling`] defaults this to `Some(3)` when not set.

Strategy-specific knobs live in EntropyOptions (entropy-search parameters) and EntanglingOptions (loose-goal Hungarian parameters). Problem-specific data (`initial`, `target`, `blocked`, `max_expansions`) remain as direct arguments.

class Strategy ¶ source

bloqade_lanes_search::solve::Strategy

Bases: Debug , Clone , Copy , StructuralPartialEq , PartialEq , Eq

Rust enum. Search strategy for the solver.

pub enum Strategy

Variants

Name Type Description
AStar — A* / Weighted A* search: `f = g + weight * h`, goal on pop. weight=1.0 is standard A* (optimal); weight>1.0 is bounded suboptimal.
HeuristicDfs — Heuristic depth-first search: fast, bounded memory, not optimal.
Bfs — Breadth-first search: finds shallowest solution, no heuristic.
GreedyBestFirst — Greedy best-first: fast, uses heuristic only (no path cost).
Ids — Iterative Diving Search: depth-first with heuristic jump-back.
Cascade { ... } Cascade: fast inner strategy first, then weighted A* bounded by inner cost. Restarts apply to the inner phase only; A* runs once with the tightest bound.
Entropy — Entropy-guided search: single-path DFS with entropy-based backtracking.
