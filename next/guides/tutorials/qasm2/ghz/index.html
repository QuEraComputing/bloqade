GHZ State Preparation with Parallelism

In this example, we will implement a Greenberger-Horne-Zeilinger (GHZ) state preparation circuit with N=2nN = 2^nN=2n qubits.

First, we will present the standard linear-depth construction in Bloqade but later we will present a log-depth construction that achieves the same result. We then take this one step further and use the fact that Bloqade (and QuEra’s neutral atom hardware!) support parallel gates, allowing for the application of the same gate across multiple qubits simultaneously. Combined with the fact that atom shuttling allows for arbitrary connectivity, we can also decrease the circuit execution depth from NNN to just nnn.

A simple GHZ state preparation circuit can be built with N−1N - 1N−1 CX gates and 111 H gate. This gives the circuit an execution depth of NNN.

Circuit vs. Execution Depth

Before going any further, it’s worth distinguishing between the concept of circuit depth and circuit execution depth. For example, in the following implementation, each CX gate instruction inside the for-loop is executed in sequence. So even though the circuit depth is log(N)=nlog(N) = nlog(N)=n, the circuit execution depth is still NNN.

Our Native Gate Set and Parallelism

Section titled “Our Native Gate Set and Parallelism”

By nature, our digital quantum computer can execute native gates in parallel in an single instruction/ execution cycle. The concept is very similar to the SIMD (Single Instruction, Multiple Data) in classical computing.

On our hardware, there are two important factors to be considered:

  1. the native gate set allows for arbitrary (parallel) rotations and (parallel) CZ gates.
  2. Our atom shuttling architecture allows arbitrary qubit connectivity. This means that our parallel instruction is not limited to fixed connectivity (for example nearest neighbor connectivity).

With this in mind, we can rewrite the layer subroutine to now use the qasm2.parallel dialect in Bloqade. Using Closures to Capture Global Variables

While bloqade.qasm2 permits a main program with arguments, standard QASM2 does not. To get around this, we need to put the program in a closure. Our Kirin compiler toolchain can capture the global variable inside the closure. In this case, the n_qubits will be captured upon calling the ghz_log_simd(n_qubits) python function. As a result, the returned QASM2 program will not have any arguments.
